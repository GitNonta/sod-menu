# ต่อการจองโต๊ะเข้าระบบร้าน (Google Sheet + Apps Script)

เว็บเมนูเป็น static (GitHub Pages) จึงไม่มีเซิร์ฟเวอร์ของตัวเอง — ฟอร์มจองจะ **POST JSON** ไปที่ URL ที่ตั้งไว้ใน
`data/menu.json` → `shop.reserve.webhook` ตัวรับที่แนะนำคือ **Google Apps Script Web App** ที่ต่อท้ายแถวลง Google Sheet
(ฟรี ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องมีบัตรเครดิต) ใช้โค้ดที่ [`reserve-webhook.gs`](../reserve-webhook.gs)

```
เว็บเมนู (มือถือลูกค้า)
   │  POST text/plain;charset=utf-8  { code, name, phone, date, time, party, note }
   ▼
Apps Script Web App  ──►  Google Sheet "Reservations" (1 แถว / 1 การจอง)
   │
   └─►  { ok: true, code: "SOD-XXXXX" }  →  เว็บขึ้นกล่อง "ได้รับคำขอจองแล้ว"
```

> ใช้ `text/plain` เพื่อ **ไม่ให้เบราว์เซอร์ส่ง CORS preflight (OPTIONS)** เพราะ Apps Script ตอบ preflight ไม่ได้
> เนื้อหายังเป็น JSON ปกติ ฝั่ง Apps Script จึง `JSON.parse` ได้เหมือนเดิม

---

## 1. สร้างสเปรดชีต

1. เปิด <https://sheets.new> สร้างไฟล์ใหม่ ตั้งชื่อ เช่น `SOD! reservations`
2. เมนู **Extensions → Apps Script** (จะเปิดสคริปต์ที่ผูกกับไฟล์นี้)
3. ลบโค้ดตัวอย่างใน `Code.gs` แล้ววางเนื้อหาทั้งหมดของ [`reserve-webhook.gs`](../reserve-webhook.gs)
4. กด **Save** (Ctrl+S) ตั้งชื่อโปรเจกต์ เช่น `sod-reserve`

## 2. ตั้งค่า Script Properties

ในหน้า Apps Script → **Project Settings (ไอคอนเฟือง) → Script properties → Add script property**

| Key | Value | จำเป็น |
| --- | --- | --- |
| `SHARED_TOKEN` | สตริงสุ่มยาว ๆ เช่น `sod-9f2c7b41e8` | แนะนำอย่างยิ่ง |
| `SHEET_ID` | ไอดีสเปรดชีตจาก URL `.../spreadsheets/d/<ไอดีนี้>/edit` | ใส่เมื่อสคริปต์ไม่ผูกกับชีต |

กด **Save script properties** แล้วเลือก **Run → setup** หนึ่งครั้ง
(ครั้งแรก Google จะขออนุญาตสิทธิ์ — เลือกบัญชี → *Advanced* → *Go to sod-reserve (unsafe)* → Allow)

ตรวจผล: ในชีตจะมีแท็บ **Reservations** พร้อมหัวตาราง
`รับเมื่อ | รหัส | ชื่อ | เบอร์โทร | วันที่จอง | เวลา | จำนวนคน | หมายเหตุ | สถานะ | โต๊ะ`

> คอลัมน์ **โต๊ะ** (J) อยู่ท้ายตารางเพื่อไม่ให้ชีตเก่าที่มีข้อมูลอยู่แล้วเลื่อนคอลัมน์
> ถ้าเคยรัน `setup()` ด้วยโค้ดเวอร์ชันก่อนหน้า ให้รันซ้ำอีกครั้งเพื่อเพิ่มหัวคอลัมน์ J
> คอลัมน์นี้เก็บได้หลายโต๊ะในช่องเดียว (คั่นด้วย `, `) — ใช้ตัวกรอง/ค้นหาแบบ "มีคำว่า A1" แทนการเทียบทั้งช่อง

## 3. Deploy เป็น Web App

1. **Deploy → New deployment → Select type → Web app**
2. ตั้งค่า
   - **Description:** `reserve v1`
   - **Execute as:** `Me (อีเมลของคุณ)`
   - **Who has access:** `Anyone` ← จำเป็น ไม่งั้นลูกค้าที่ไม่ได้ล็อกอินจะส่งไม่ได้
3. **Deploy** แล้วคัดลอก **Web app URL** (ลงท้าย `/exec`)

### ผังโต๊ะ (กดจองจากผัง)

ในชีตจองเพิ่มบล็อก `plan` ไว้ใน `shop.reserve` — จุดที่กดได้คือพิกัดเป็น **เปอร์เซ็นต์ของรูป**
ไม่ใช่พิกเซล เปลี่ยนรูปหรือขนาดจอแล้วยังตรง:

```json
"plan": {
  "enabled": true,
  "image": "images/floorplan.jpg",
  "tables": [
    { "id": "24", "label": "24", "x": 60.3, "y": 40.6, "w": 5.4, "h": 5.4 },
    { "id": "A10", "label": "A10", "x": 93.1, "y": 73.8, "w": 6.4, "h": 4.8 }
  ]
}
```

- `x`/`y` = จุดกึ่งกลางป้ายโต๊ะบนรูป (0–100) — `w`/`h` = ขนาดพื้นที่กด (0–100)
- `id` คือค่าที่บันทึกลงคอลัมน์ **โต๊ะ** ของชีต — ใช้ตัวเลข/ตัวอักษรสั้น ๆ (`24`, `A10`, `VIP2`)
- **โต๊ะคู่** (ร้านตั้งติดกันเป็น 1 โต๊ะ): `A1 + A2`, `A3 + A4`, `A5 + A6`, `A7 + A8`, `A9 + A10`, `B2 + B3`, `B4 + B5`, `B6 + B7`, `B8 + B9`
  โดยใส่ `"ids": ["A1", "A2"]` — ทำให้การจองเดิมที่บันทึกเป็น `A1` หรือ `A2` ยังขึ้นเป็น "ถูกจอง" ที่ช่องเดียวกัน
  (ดูจากช่องที่มี `"ids"` ใน `data/menu.json` — ถ้ามีคู่อื่นอีก เพิ่มอีกรายการในรูปแบบเดียวกัน)
- **เลือกได้หลายโต๊ะ**: ลูกค้าแตะเพิ่ม/แตะซ้ำเพื่อเอาออกได้ คอลัมน์ **โต๊ะ** จึงเก็บเป็นข้อความคั่นด้วยจุลภาค เช่น `A1 + A2, 22, 9` (ยาวไม่เกิน 40 ตัวอักษร)
- ผังทั้งหมด 106 โต๊ะของร้านอยู่ใน `data/menu.json` แล้ว (ตัวเลข 1–45, A1–A17, B1–B31, SB1–SB8, VIP1/2/5/6/7)
- ถ้าจะเพิ่มโต๊ะ: เปิดรูปในโปรแกรมแต่งภาพ อ่านพิกัดเป็น % แล้วเพิ่ม entry ตามรูปแบบข้างบน
- **สถานะถูกจอง** มาจาก `?action=busy&date=YYYY-MM-DD` ของ Apps Script เดียวกัน
  ซึ่งคืนเฉพาะ `{table, time}` ของวันที่นั้น (ไม่มีชื่อ/เบอร์) จึงเปิดให้เรียกได้โดยไม่ต้องมี token
  — ถ้าอยากปิด ให้ลบ `if (action === 'busy')` ใน `doGet` ออก

### ทดสอบด้วย curl

```bash
curl -s -X POST "https://script.google.com/macros/s/XXXX/exec?token=sod-9f2c7b41e8" \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"code":"SOD-TEST1","name":"ทดสอบ","phone":"0812345678","date":"2026-11-08","time":"19:30","party":4,"table":"24","note":"curl"}'
```

 sollte ตอบ `{"ok":true,"code":"SOD-TEST1","row":2}` และมีแถวใหม่ในชีต (ลบแถวทดสอบทิ้งได้)

ตรวจสถานะแบบไม่คืนข้อมูลลูกค้า: เปิด URL เดียวกันด้วย GET → `{"ok":true,"service":"sod-reserve","bookings":N,...}`

ทดสอบรายการของวันนั้น (ใช้ในหน้ารายการจองของพนักงาน ข้อ 6):

```bash
curl -s "https://script.google.com/macros/s/XXXX/exec?action=list&date=2026-11-08&token=sod-9f2c7b41e8"
# → {"ok":true,"date":"2026-11-08","count":1,"people":4,"rows":[{"time":"19:30",...}]}
```

## 4. เปิดใช้บนเว็บ

แก้ `data/menu.json`

```json
"reserve": {
  "enabled": true,
  "hint": "กรอกข้อมูลให้ครบ แล้วรอร้านยืนยันอีกครั้ง",
  "open_time": "17:00",
  "close_time": "02:00",
  "max_party": 20,
  "max_days": 30,
  "webhook": "https://script.google.com/macros/s/XXXX/exec?token=sod-9f2c7b41e8",
  "line_url": "https://line.me/R/oaMessage/@yourlineid/?",
  "phone": "0812345678"
}
```

- `webhook` — URL จากข้อ 3 (ใส่ `?token=...` ต่อท้ายเสมอถ้าตั้ง `SHARED_TOKEN`)
- `line_url` — ถ้าใส่ลิงก์ `oaMessage` ของ LINE OA ปุ่ม "ส่งให้ร้านทาง LINE" จะเปิดแชทร้านพร้อมข้อความ (ถ้าเว้นว่างจะใช้ตัวแชร์ของ LINE)
- `phone` — ใส่แล้วจะมีปุ่ม "โทรหาร้าน" ในหน้าสำเร็จ
- **บวกเลข `version`** (เช่น `1.0.7` → `1.0.8`) และ `ASSET_VERSION` ใน `app.js` ให้ตรงกัน แล้วบวก `?v=` ของ `style.css`/`app.js` ใน `index.html` ด้วย
- commit + push → GitHub Pages อัปเดตเองใน 1–2 นาที

## 5. ฝั่งร้าน: ดูและยืนยันการจอง

- เปิดชีต **Reservations** เรียงใหม่→เก่าได้เลย คอลัมน์ **สถานะ** มี dropdown `รอยืนยัน / ยืนยันแล้ว / ยกเลิก`
- แนะนำทำ **Filter view** หรือ **Slicer** ตามวันที่, หรือสร้างแท็บสรุปด้วย `=COUNTIFS(Reservations!E:E, TODAY())`
- อยากได้แจ้งเตือนเข้า LINE/LINE Notify หรืออีเมลทุกครั้งที่มีการจอง: เพิ่มใน `doPost` หลัง `appendRow` เช่น

```javascript
  MailApp.sendEmail({
    to: Session.getActiveUser().getEmail(),
    subject: 'จองใหม่ ' + code + ' · ' + payload.date + ' ' + payload.time,
    body: payload.name + ' ' + payload.phone + ' · ' + payload.party + ' คน\n' + (payload.note || ''),
  });
```

> แก้โค้ดแล้วต้อง **Deploy → Manage deployments → แก้ไข (ดินสอ) → Version: New version → Deploy**
> ไม่งั้น URL เดิมยังรันโค้ดเก่า

## 6. หน้ารายการจองวันนี้ (`today.html`)

พนักงานเปิด **`https://gitnonta.github.io/sod-menu/today.html`** เพื่อดูรายการจองของวันนั้นบนมือถือ
โดยไม่ต้องเปิด Google Sheet — หน้าเว็บยังเป็น static, อ่านข้อมูลผ่าน Apps Script และต้องมี token เท่านั้น

1. ถ้าเพิ่งวางโค้ดที่เพิ่ม `list_` ให้ **Deploy → Manage deployments → New version → Deploy** ก่อน
2. เปิด `today.html` ครั้งแรก → กรอกรหัส `SHARED_TOKEN` (เก็บใน `localStorage` ของเครื่องนั้น)
   หรือเปิดด้วยลิงก์ `today.html?token=<รหัส>` ครั้งเดียว ระบบจะจำแล้วลบ token ออกจาก URL ให้
3. เลือกวันที่ (ค่าเริ่มต้น = วันนี้) · กด **รีเฟรช** หรือปล่อยให้รีเฟรชเองทุก 60 วินาที

หน้าเว็บเรียก endpoint เดิมที่ต่อท้ายด้วย

```
?action=list&date=YYYY-MM-DD&token=<SHARED_TOKEN>
→ { "ok": true, "date": "2026-11-08", "count": 1, "people": 4,
    "rows": [ { "time": "19:30", "name": "นนท์", "phone": "0812345678", "party": 4,
                "note": "", "status": "รอยืนยัน", "code": "SOD-XXXXX", "created_at": "2026-11-07 04:31" } ] }
```

- `action=list` **บังคับ** token เสมอ (ถ้ายังไม่ตั้ง `SHARED_TOKEN` จะตอบ error) เพราะคืนชื่อ/เบอร์ลูกค้า
- ไม่ส่ง `date` = วันนี้ตามเวลาไทย (`Asia/Bangkok`); รายการเรียงตามเวลา
- หน้านี้เป็น **อ่านอย่างเดียว** — ยืนยัน/ยกเลิกยังทำในชีต (แก้คอลัมน์ **สถานะ**) แล้วหน้ารายการจะอัปเดตตามรอบรีเฟรช
- อย่าแชร์ลิงก์ที่มี token และไม่ต้องลิงก์หน้านี้จากหน้าเมนู (มี `noindex` กันอยู่แล้ว)

## 7. ความปลอดภัยและความเป็นส่วนตัว

- URL `/exec` เป็น public โดยธรรมชาติ ใครรู้ก็ยิงได้ → ตั้ง `SHARED_TOKEN` และ **อย่าโพสต์ URL นี้ที่อื่น**
- `doPost` กรองข้อมูลซ้ำด้วยรหัสการจอง (`code`) และตรวจรูปแบบเบอร์/วันที่/เวลา/จำนวนคนก่อนบันทึก
- เก็บเท่าที่จำเป็น: ชื่อ, เบอร์, วันเวลา, จำนวนคน, หมายเหตุ — ไม่เก็บอีเมล/IP
- ตาม PDPA: แจ้งวัตถุประสงค์ที่ใช้ข้อมูล (ยืนยันการจอง/ติดต่อกลับ), จำกัดคนที่เข้าถึงชีต, และลบข้อมูลเป็นระยะ
  (เช่น เพิ่มสูตร/สคริปต์ลบแถวที่เก่ากว่า 90 วัน)
- ตั้งสิทธิ์ไฟล์ชีตเป็น "Restricted" ให้เฉพาะทีมร้าน แล้วแชร์เฉพาะคนที่ต้องใช้
- สำรองข้อมูล: **File → Make a copy** เป็นรายเดือน หรือตาราง `=IMPORTRANGE` ไปยังชีตสำรอง

## 8. ถ้าไม่ใช้ Google Sheet

| ทางเลือก | เหมาะกับ | หมายเหตุ |
| --- | --- | --- |
| **Apps Script + Sheet** (คู่มือนี้) | ร้านเล็ก–กลาง, ฟรี, ดูผ่านมือถือได้ | ไม่มี preflight, ต้อง deploy ใหม่เมื่อแก้โค้ด |
| Formspree / Web3Forms | อยากได้อีเมลแจ้งเตือนทันที | ต้องสมัครและเอา endpoint มาใส่ `webhook` (payload เดิมใช้ได้) |
| Supabase / Firebase | ต้องการหลังบ้านจริง (พนักงานล็อกอิน, จัดการโต๊ะ) | ต้องมีโปรเจกต์และ API key; ต้องเปิด CORS ให้โดเมน `gitnonta.github.io` |
| Google Form | ง่ายสุด ไม่ต้องเขียนโค้ด | ผู้ใช้ต้องออกจากหน้าเว็บไปกรอกฟอร์ม (เสียอารมณ์และเสีย conversion) |

ทุกทางใช้สัญญาเดิม: `POST` JSON `{code, name, phone, date, time, party, note, created_at, source}`
และตอบกลับ `{ "ok": true }` — ถ้าตอบ `{"ok": false}` หรือ HTTP ไม่ใช่ 2xx เว็บจะขึ้นข้อความ
"ส่งอัตโนมัติไม่สำเร็จ — กรุณาส่งข้อความทาง LINE หรือโทรหาร้าน" และยังมีรหัสจองให้ลูกค้าใช้

## 9. แก้ปัญหา

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
| --- | --- | --- |
| เว็บขึ้น "ส่งอัตโนมัติไม่สำเร็จ" | URL ผิด/ยังไม่ deploy/สิทธิ์เป็น "Only myself" | เปิด URL ด้วย GET ในเบราว์เซอร์ต้องเห็น `{"ok":true,...}` และตั้ง Access = Anyone |
| ตอบ `{"ok":false,"error":"unauthorized"}` | token ไม่ตรงหรือไม่ได้ส่งมา | ตรวจ `?token=` ใน webhook และค่า `SHARED_TOKEN` |
| ไม่มีแถวใหม่ แต่เว็บขึ้นสำเร็จ | ชีตถูกแก้โครงสร้าง/แท็บไม่ชื่อ `Reservations` | รัน `setup()` อีกครั้งหรือเปลี่ยนชื่อแท็บให้ตรง |
| เบอร์โทรขึ้นเป็นตัวเลขไม่มี 0 | คอลัมน์ D ไม่ได้ตั้งรูปแบบข้อความ | รัน `setup()` (ตั้ง `D:D` เป็น `@`) |
| แก้โค้ดแล้วพฤติกรรมไม่เปลี่ยน | ยังใช้ deployment version เก่า | Manage deployments → New version → Deploy |
| ข้อความ error ใน Apps Script | ยังไม่ได้อนุญาตสิทธิ์/ยังไม่ตั้ง `SHEET_ID` | ดู Executions ในหน้า Apps Script |
| `today.html` ขึ้น "รหัสผ่านร้านไม่ถูกต้อง" | token ต่างจาก `SHARED_TOKEN` หรือยังไม่ได้ตั้ง | ล้างค่าใน localStorage (`sod-admin-token`) แล้วกรอกใหม่/ตรวจ Script Properties |
| `today.html` ขึ้น "โหลดรายการไม่สำเร็จ" | ยัง deploy เวอร์ชันเก่าที่ไม่มี `action=list` / URL ผิด | Manage deployments → New version → Deploy แล้วรีเฟรช |
| ผังไม่ขึ้น / กดโต๊ะไม่ได้ | `shop.reserve.plan` ไม่มี `tables` หรือ `enabled: false` | ตรวจ JSON ใน `data/menu.json` และชื่อไฟล์ `images/floorplan.jpg` |
| ผังขึ้นแต่ไม่มีสถานะถูกจอง | ยังไม่ deploy เวอร์ชันที่มี `action=busy` หรือยังไม่ตั้ง `webhook` | Deploy เวอร์ชันใหม่ + ตรวจ `shop.reserve.webhook` |

## ล็อคโต๊ะสำหรับร้าน (admin)

บางวันร้านไม่รับจองบางโต๊ะ (ปิดซ่อม / ต่อโต๊ะให้ลูกค้า walk-in) — ใช้ระบบล็อคได้โดยไม่ต้องแก้เว็บ

- เปิด **`today.html`** พร้อมรหัสผ่านร้าน (`?token=…` หรือกรอกในช่อง) → กล่อง **“ล็อคโต๊ะ”** ท้ายหน้า
- เลือกวันที่ด้านบน → ใส่เลขโต๊ะ (หลายโต๊ะคั่นด้วยจุลภาค เช่น `12, A1 + A2`) → กด **ล็อคโต๊ะ**
- โต๊ะที่ล็อคจะขึ้นลายทแยงสีเทา **“ปิดโดยร้าน”** บนผังของลูกค้า และจองไม่ได้
- ต้องการเปิดคืน → กด **ปลดล็อค** ข้างรายการในกล่องเดียวกัน

ข้อมูลเก็บในแท็บ **`TableLocks`** ของสเปรดชีต (สร้างให้อัตโนมัติเมื่อรัน `setup()` หรือเมื่อล็อคครั้งแรก)

| คอลัมน์ | ความหมาย |
| --- | --- |
| A `วันที่` | วันที่ล็อค (YYYY-MM-DD) |
| B `โต๊ะ` | เลขโต๊ะ หรือคู่ `A1 + A2` |
| C `หมายเหตุ` | เหตุผล เช่น `ปิดซ่อม` (แสดงใน tooltip ของผัง) |
| D `บันทึกเมื่อ` | เวลาที่ล็อค |

API ที่เพิ่ม (ต้องมี `SHARED_TOKEN` ทุกตัว):

```
GET  ?action=locks&date=YYYY-MM-DD&token=…        → { ok, date, locks: [{ table, note, at }] }
POST { "action": "lock",   "token": "…", "date": "YYYY-MM-DD", "tables": ["12","A1 + A2"], "note": "ปิดซ่อม" }
POST { "action": "unlock", "token": "…", "date": "YYYY-MM-DD", "tables": ["12"] }
                                                    → { ok, action, date, changed: [...], locks: [...] }
```

- `?action=busy` ของลูกค้าจะคืนโต๊ะที่ล็อคมาด้วยในรูปแบบ `{ "table": "12", "time": "", "locked": true }`
  (ไม่มีชื่อ/เบอร์ลูกค้า) เว็บจึงแสดงสถานะได้โดยไม่ต้องใช้ token
- การล็อคเป็นราย **วัน** — ล็อควันนี้ไม่กระทบวันอื่น


## ทางเข้าหน้า `today.html` และการแจ้งเตือนจองใหม่

- **ทางเข้าลับ**: ที่หน้าเมนู **แตะโลโก้ร้าน 5 ครั้งติดกัน** (ภายใน ~1.6 วินาที) → เปิด `today.html`
  ไม่มีลิงก์หรือปุ่มให้ลูกค้าเห็น จึงไม่ต้องกลัวแขกหลงเข้ามา (หน้านี้ยังมี `<meta name="robots" content="noindex">`)
- **แจ้งเตือนเมื่อมีจองใหม่**: หน้า `today.html` รีเฟรชเองทุก 1 นาที (และทุกครั้งที่สลับกลับมาที่แท็บ)
  ถ้ามีรหัสจองใหม่ที่เครื่องนี้ยังไม่เคยเห็น จะขึ้นแบนเนอร์ “🔔 จองใหม่ N รายการ” พร้อมเวลา/ชื่อ/โต๊ะ และกด ✕ ปิดได้
- อยากได้เสียง/ป๊อปอัปของระบบด้วย → กดปุ่ม **“🔔 เปิดการแจ้งเตือนบนเครื่องนี้”** ใต้ช่องวันที่ (ขอสิทธิ์ Notification ครั้งเดียว เก็บในเบราว์เซอร์)
  ต้องเปิดหน้านี้ผ่าน **https** (GitHub Pages ใช้ได้) และ permission จะถูกจำ per-อุปกรณ์
- รหัสจองที่เห็นแล้วถูกจำไว้ใน `localStorage` คีย์ `sod-seen-bookings` (เก็บ 5 วันล่าสุด) รีเฟรชหน้าซ้ำจึงไม่เตือนซ้ำ
  — ถ้าต้องการล้าง ให้ลบ key นี้ออก หรือกดล้างข้อมูลเว็บไซต์


## แจ้งเตือนจองใหม่เข้า LINE กลุ่มร้าน

ทุกครั้งที่มีคนจองใหม่ (หลังเพิ่มแถวในชีตสำเร็จ) สคริปต์จะ push ข้อความเข้ากลุ่ม LINE ของร้านผ่าน **LINE Messaging API**
ถ้ายังไม่ตั้งค่า ระบบจะข้ามการแจ้งเตือนไปเงียบ ๆ — การบันทึกจองยังทำงานปกติ

**ข้อความที่ส่ง**

```
🔔 จองใหม่ · SOD! signature
18:00 น. · 7 พ.ย.
นนท์ · 2 คน · โต๊ะ 24
081-234-5678
หมายเหตุ: ขอโต๊ะริมหน้าต่าง
รหัส SOD-AAAA1
```

**ขั้นตอนติดตั้ง**

1. สร้าง **LINE Official Account** ของร้าน แล้วเปิดใช้ **Messaging API** ที่ <https://developers.line.biz/console/>
   (เลือก provider → สร้าง channel ชนิด Messaging API)
2. ในแท็บ **Messaging API** ของ channel กดออก **Channel access token (long-lived)** แล้วคัดลอกไว้
3. เพิ่มบอทของร้าน (สแกน QR ในแท็บ Messaging API) เข้ากลุ่ม LINE ที่พนักงานอยู่
4. ตั้ง **Webhook URL** ชั่วคราวเป็น URL เว็บแอปของสคริปต์ พร้อม token:
   `<URL /exec>?token=<SHARED_TOKEN>` แล้วกด **Verify** / พิมพ์ข้อความอะไรก็ได้ในกลุ่ม 1 ครั้ง
   → สคริปต์จะจด `LINE_TO` (groupId ของกลุ่มนั้น) ลง Script Properties ให้อัตโนมัติ
   (เสร็จแล้วจะปิด Webhook หรือคงไว้ก็ได้ — endpoint นี้ตอบ `{"ok":true,"line":"captured"}`)
5. ไปที่ Apps Script → ⚙️ **Project Settings → Script Properties** ตั้งค่า
   | Property | ค่า |
   | --- | --- |
   | `LINE_CHANNEL_TOKEN` | channel access token จากข้อ 2 |
   | `LINE_TO` | groupId (จดอัตโนมัติจากข้อ 4) หรือ userId ของพนักงานที่ต้องการให้เตือนเดี่ยว |
6. ทดสอบ: เลือกฟังก์ชัน **`testLine`** แล้วกด Run → ดูข้อความในกลุ่ม + ผลใน Execution log (`sent` / `failed` / `skipped`)
   - `skipped` = ยังไม่ได้ตั้ง property, `failed` = token ผิด / บอทไม่ได้อยู่ในกลุ่ม (อ่าน error ใน log)

> ทุกครั้งที่แก้ไฟล์นี้ต้อง **Deploy → Manage deployments → แก้เวอร์ชันใหม่ (New version)** ก่อน ระบบ GitHub Pages จึงจะเห็นการเปลี่ยนแปลง
> ข้อความจะส่งเฉพาะการจองใหม่ ไม่ส่งตอนล็อคโต๊ะหรือตอนพนักงานเปลี่ยนสถานะ
